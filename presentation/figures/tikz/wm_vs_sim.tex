% State world model vs planning in the simulator directly (deck slide after "How the state world model works").
% Moving the pusher and the contact check work the same way in both, so only the letter's motion is compared, with
% the reasons for the speed gap: the state world model runs all plans as one batch on the GPU, one small network pass
% per step and one exact distance for contact; the simulator steps one plan at a time on the CPU, restores the scene
% for every plan and runs 10 physics substeps with collision checks per step.
% Timing of one teacher decision, 1,024 plans x 48 controls from one state, each scored at every control
% (measured 2026-11-12): state world model plus scoring on the GPU 0.066 s; the official simulator (restore the state,
% 10 physics substeps per control, coverage at every control, no rendering) 14.2 s on one CPU process. Error of the
% state world model: median 0.25 px 8 controls ahead (wm_accuracy).
