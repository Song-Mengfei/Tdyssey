# Shared writer reservations and saved-report output guards

This change is IO only: no simulator construction, physics replay, model, optimizer or raw precision changes. The calibration-v1 executed source/raw/gate remain untouched. The root-owned resource-policy-v2.json is read and hashed, never modified by this module.

`ResourceReservation(output, shared_roots, resource_policy_path, owner, role='collection'|'postprocess', reserve_bytes=None)` is a context manager. It exposes `policy`, `policy_sha256`, `reservation_id`, `last_snapshot`, `remaining_bytes`; methods `ensure_capacity(n)`, `write_bytes(path,payload)`, `commit_external_write(path,previous_size=...)` and `snapshot()`. Collector trajectory and runs metadata paths may be anywhere inside the verified collection root. `None` keeps an available default512MiB administrative policy; productioncal2/formal use the explicit root-owned1.5GiB policy.

The collection root's `.resource.lock` is a real OS byte lock on Windows (`msvcrt.locking`), with a same-process thread mutex; POSIX uses `flock`. Snapshot/check/reservation mutation is serialized in `resource-reservations.json`. At most two collectors can own leases, and no postprocessor overlaps a collector. Each writer retains its lease until all trajectory outputs have been saved. A peer cannot allocate the same remaining headroom independently. The first collector leaves the declared32MiB concurrent allowance. Shared3GiB/256MiB atomic reserve is checked before the per-collection cap, with the separate128MiB postprocessing allocation held throughout collection.

Checkpoint bytes are compressed in memory by the caller, then passed to `lease.write_bytes`. An already allocated writer can use its remaining lease without rescanning the entire shared filesystem for every checkpoint; a growing allocation and each boundary snapshot are checked again. The short atomic file write stays inside the common OS lock, preventing another check from interpreting visible old+temp files as unreserved external output. OneMiB remains for small administrative records. Shared scans always cover actual existing files; missing roots remain disclosed. A crashed process's pending lease is not silently cleared. An owner audit is required, and no automatic retry follows.

The postprocessing lease has128MiB for all managed report outputs, including files already present under report/ and REPORT.md. Every PNG is rendered to an in-memory buffer, every CSV/JSON/HTML/text is serialized to known bytes, then a live shared/free check occurs before an atomic write. Net committed growth reduces its remaining allocation; the old file plus temporary replacement must fit the remaining peak budget. This does not spend the256MiB atomic reserve.

Each video is checked before encoder startup. The encoder has a bounded file limit (at most8MiB encoded payload per6.4s clip), plus a reserved raw-frame-sized packet margin; all video files together remain64MiB. Actual output is charged even if encoding fails. Actual frames/fps are decoded afterward; a file-limit-truncated clip is retained as failure evidence, never represented as a completed video. No interpolation, speed-up, simulated replay or change to actual RGB/labels occurs. The saved-only formatter records its source/resource policy identity and initial guard snapshot.

Validation: nine core synthetic IO tests passed, including two real independent process IDs sharing the same OS lock/ledger; third-writer rejection; joint near-cap expansion rejection; guard failure before file creation; preexisting report/overwrite accounting; and default-policy compatibility. A separate targeted test passed actual CPU H264 encoding/decoding of a three-frame synthetic fixture and exact CSV guarded output. No physical or model steps occurred. The first fixture run in Windows AppContainer's default temporary folder could not atomically rename files; fixtures were moved to a resolved project-artifacts temporary directory. This was not a production collector failure. No global permissions or dependencies were changed.

Evidence: core-tests.log and report-encoder-test.log. The production helper source is frozen after these tests; no cal2 worker has been started by this agent. Old formatter source and its hash are in before.json/original_contact_pilot_report.py.
